## Purpose

oversightengineering.com is the public record of the work cited in Pravin
Khandke's fellowship applications (BCS Fellow first, IET Fellow next). Today
it is eight text-dense pages with almost no links and no photo. The rebuild
makes it scannable, links every venue, shows the person, and adds a private
evidence store plus an actionable checklist. The reference sites were shown
by the user as examples; the judgement call is what a professional evidence
record needs, and nothing more.

## Site architecture

Single scrolling home page as the browsable front, generated by `build.py`.
The four criterion detail pages remain, trimmed, each linked from its home
section with a full-record link. This gives assessors depth and gives
everyone else a scannable page.

Home page sections, in order:

| Anchor | Content |
|---|---|
| hero | Photo, name, tagline row, badge chips, stat counters, connect row |
| about | Three paragraphs maximum, arc from retail to automotive to financial |
| invention | Two cards: remittance reconciliation pipeline, event-driven retail backbone |
| leadership | Three cards: Cox platform retirement, canonical data model, financial services integration |
| mentoring | Three cards: engineers developed, sponsored capstone, children's AI safety standard |
| influencer | Five tabbed rows: Speaking, TPC, Peer review, Writing, Judging |
| recognitions | Certificate thumbnail grid with links to PDFs or registers |
| publications | Rows: two papers, five technical articles, each one line with link |
| education | Compact degree list and a four-role work history table |

Pages that fold into home sections and are removed: memberships, publications,
talks, peer-review. Pages retained as trimmed detail pages: invention,
consultancy, mentoring, standing. `docs/iet/index.html` remains a stub until
the IET application is drafted, and says so.

`build.py` stays the single generator. Page content is one `add()` call for
the home page plus trimmed calls for the four detail pages. Navigation is
generated. The print stylesheet for assessors is kept and updated.

## Visual design

- Palette: near-white background, ink text, one accent. Reference sites use
  a deep teal blue on light blue; adopt a restrained variant (deep blue
  accent on white) so it reads as evidence, not marketing.
- Type: serif display for name and section headings, sans for body. The
  current Archivo and Spectral pairing already matches this; keep it and
  drop the weight count rather than swap families.
- Hero: circular photo left or right, name set large with the surname in the
  accent colour, bordered badge chips for IEEE Senior Member, RSS Fellow,
  SEFM Eminent Fellow, right-aligned stat counters (26 years, 73 reviews,
  26 venues, 4 committees).
- Sections: heading with rule line, cards with a tag row, lists as rows not
  paragraphs.
- Responsive at phone width. No horizontal scroll. 16px side gutter minimum.
- Print stylesheet kept.

## Content rules

Unchanged from the README, because an assessor reads the site beside the form:

- Zero em dashes and en dashes, zero semicolons
- No sentence with an inline comma list of three or more items
- No conclusory adjectives or promotional language
- Every checkable claim carries a source line

Text reduction rule: no paragraph on the home page longer than three
sentences. Detail pages keep their claims but lose preamble sentences.
The current paragraphs survive only as card bodies.

Fellow items (senior professional standing, sustained responsibility, and
the two sponsor requirements), mark what the rebuild itself closes (venue
links, thumbnails), and produce a missing-items checklist the user can act
on, each item tagged site, file, or who produces it.

## Recognitions thumbnails

Published subset, held in `docs/assets/img/certs/`:

- IEEE Senior Member, SAS SEFM, RSS Fellow, each linking to its verification
  URL where one exists
- Keynote and TPC certificates on file (AIIoT, ICCUBEA, ICDCECE, ICoIAS,
  MeditCom, NGSME), linking to the PDF

Excluded from publication: review confirmations (third-party personal data),
anything employer-confidential, anything with commercial figures. Thumbnails
are generated from the certificate images or PDFs at small size so the page
stays light.

## Error handling and verification

Build must pass with `python3 build.py` and no hand edits in `docs/`.
Verification pass before commit:

1. Browse the generated home page and all four detail pages at 375px and
   1280px widths, no horizontal scroll.
2. Every external link checked, target 200 or a named exception.
3. Every image present with alt text.
4. Print stylesheet renders the home page legibly.
5. Screenshots to the user before anything is committed.
